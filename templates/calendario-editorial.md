# Calendário Editorial — 12 Semanas

Cadência fixa: **3 posts por semana** (Terça / Quinta / Sábado). Repetir o padrão sempre — consistência de formato constrói reconhecimento.

---

## Padrão de Cada Semana

### Terça — Post de Anúncio
Objetivo: gerar expectativa e mostrar ritmo de entrega constante.

```
Construí um [PROJETO] porque [PROBLEMA REAL DO MERCADO].

Stack: [ferramenta 1] + [ferramenta 2] + [ferramenta 3]
Aprendizado principal: [1 insight técnico em 1 frase]

GitHub: [link]

Semana que vem: [próximo projeto]

#DataEngineering #Databricks #Python
```

### Quinta — Post de Deep Dive Técnico
Objetivo: demonstrar profundidade, não só entrega. Este é o post que recrutador técnico lê com atenção.

```
Aprendizado técnico da semana: [insight específico]

[Trecho de código, gráfico de antes/depois, ou print de resultado]

Por que isso importa: [1-2 frases conectando com problema real de produção]

Documentação completa: [link do README]

#EngenhariaDeDados #DataQuality
```

### Sábado — Carrossel ou Artigo de Fechamento
Objetivo: consolidar a semana em formato mais visual/compartilhável.

```
De [estado inicial] para [estado final] em uma semana.

[Imagem: arquitetura, dashboard, ou métrica visual]

Resultado: [1 métrica concreta, ex: "query de 30s para 200ms"]

Portfólio completo até aqui: [link do portfolio-overview]
```

## Regras de Ouro

1. **Nunca postar sem o link do GitHub funcionando.** Um post sem repositório navegável é só uma promessa.
2. **Responder todo comentário em até 24h.** Engajamento é o que valida o Gate 1 e o Gate 4.
3. **Nunca prometer no post o que o projeto não entrega.** Honestidade técnica > hype.
4. **Reaproveitar linguagem simples.** Recrutadores de RH também leem — não escrever só para engenheiros.
